# 用户、家庭与测试数据隔离

## 本轮状态与用户决定

本轮只开发和本地验收，不推送、不部署、不修改正式站环境变量，也不清空正式站。

用户已明确将原先“保留旧数据迁移”的计划改为：**验收确认后清空正式站全部业务数据，包括账号、聊天、记忆、积分、家庭资料。**这不是当前立即执行的授权。正式清空仍须在验收确认、维护和初始化保护就绪后进行。

## 环境隔离

- `npm run test:server -- --build`：新建 `.test-runs/run-*` 独立目录和 `.next-test` 构建目录，只监听本机，默认端口 3887。
- 每次启动清除继承的数据库、Neon、Blob、模型、声音、推送凭据。模型及声音走本机模拟服务；通知使用临时测试密钥和测试定时任务令牌。
- 默认开发模式 `npm run test:server`；复用已完成测试构建 `npm run test:server -- --start`。`YIBAN_TEST_PORT` 可指定其他本机端口。
- 测试必须提供独立数据目录；目录不可写直接拒绝，不回退到真实用户目录。测试/预览不会自动复制旧项目数据库和上传文件。
- 数据库保存 `system/environment_binding`。非正式环境必须声明 `YIBAN_DATABASE_ENVIRONMENT` 且匹配已有绑定，正式库标记不允许被预览环境使用。
- 本机进程若携带正式数据库连接但缺少匹配声明，会在执行查询前失败；Preview 未初始化标记也会失败。它不会自动把一个生产副本改绑为测试库。
- 浏览器测试先检查 `/api/auth/status` 的环境，拒绝在正式站建立测试账号或发放测试积分。主动联系的离线时间模拟只接受当前本机隔离运行目录。

### 云端 Preview 的上线配置

本轮未创建新的 Neon 云资源，也未变更现有 Vercel 配置。验收后上线时，需要为 Preview 提供独立空库；不能继续把正式 `DATABASE_URL` 同时分配给 Production 和 Preview。

1. 新建独立、空的测试数据库，不复制私人用户数据。
2. 安全配置该空库的 `DATABASE_URL`，运行 `npm run db:environment -- --environment=preview`，这是只读预检。
3. 核对目标指纹，再显式加 `--apply --confirm-new-database=<预检指纹>`，只创建环境标记。工具拒绝绑定已有业务表的库，也拒绝修改生产标记。
4. Vercel Preview 单独配置这个连接和 `YIBAN_DATABASE_ENVIRONMENT=preview`；Production 保持正式连接。声音、模型等计费凭据也应按环境单独配置。
5. 在隔离 Preview 再验证后，才安排正式维护、重置和发布。未配置完成时，新代码的 Preview 会拒绝连接，而不会使用生产数据兜底。

已有旧版本 Preview 的环境是部署时固化的，后续上线时还须停用或重建带有正式数据库连接的旧预览部署；仅修改环境变量不会改变已经运行的旧部署。

## 权限模型

| 数据 | 隔离范围 |
| --- | --- |
| 家庭记忆、成员、纪念日、成长记录、家人配音缓存、家庭设置 | 当前家庭 |
| 会话、消息、人格、长期记忆、个人音色、心情、主动联系 | 当前用户 |
| 钱包与积分流水 | 当前用户；发放权属于平台管理员 |
| 上传文件 | 本人，或符合当前家庭的共享/记忆引用权限 |
| 邀请码 | 创建它的家庭和服务器指定角色，单次使用 |

请求通过可信登录会话建立 AsyncLocalStorage 范围，数据库查询附带该范围。修改、删除、比较更新、批量文档事务都校验归属。没有登记隔离策略的新集合，在用户请求中默认拒绝访问。

账号与家庭采用独立成员关系，账号可切换自己已加入的家庭，不能通过提交任意 `familyId` 加入别人家庭。创建家庭是原子操作，私人伴侣、聊天与余额不随家庭切换复制或重置。不同家庭的固定设置 ID 分别存储。

家庭管理员只能管理本家庭账号和资料，不能访问他人的私人聊天，也不能凭家庭管理员身份发放平台积分。移除家人只撤销对应家庭关系；对方其他家庭和私人资料不删除。没有剩余家庭的旧账号会停用，其会话不能再使用。

平台管理员首次初始化产生，并记录独立平台身份；普通家庭管理员的邀请码不授予平台身份。正式站首次初始化需要 `YIBAN_SETUP_TOKEN`，避免清空后被匿名访客抢先注册。

所有动态私有响应及媒体标记 `Cache-Control: private, no-store` 和 `Vary: Cookie`，防止同一浏览器换账号后复用旧 HTTP 缓存。已下载到用户设备的内容无法由服务端追溯撤回。

当前防护是服务端权限和带范围的 SQL 查询，**没有宣称已经启用 PostgreSQL RLS**。数据库连接仍只供服务端使用，不能交给前端用户。

## 聊天查询

- 消息按 `userId + threadId` 在数据库筛选，不再读取全平台消息后过滤。
- 历史会话按账号、归档状态、置顶、时间排序，数据库分页，每页 50 条。
- 消息查找/收藏在数据库沿当前分支查询，每页 40 条；隐藏分支不进入搜索结果。
- 未读统计在数据库遍历当前分支，只返回所需元数据。每条父子关系都校验账号与会话；`UNION` 终止损坏的循环引用。
- 添加所有者/会话/时间、所有者/更新时间和家庭范围的表达式索引。测试检查 SQLite 查询计划实际使用会话索引。
- 单个会话的完整历史/多版本读取继续保留，没有为减少数据量而截断旧记录。更长会话的向上分页可以后续单独扩展。
- 用 PGlite 的本地 PostgreSQL 引擎执行实际生产 Neon 适配器生成的 SQL，验证 JSONB 查询、索引、递归分支、事务和权限；这不等于已经在正式库进行压力测试。

## 正式清空：仅准备，尚未执行

默认命令 `npm run db:reset-plan -- --environment=<环境>` 只读显示目标指纹、记录数量和待删除私有 Blob 数量，不打印业务内容或密钥。

真正的正式清空要求全部具备：

- 用户完成验收并确认清空；授权文件包含目标指纹、`approved: true`、`acceptanceConfirmed: true`、`scope: all-business-data`。
- 正式站已部署维护模式 `YIBAN_MAINTENANCE_MODE=1`，并设置新的 `YIBAN_SETUP_TOKEN`。
- 工具通过指定 `YIBAN_PRODUCTION_URL` 实际验证维护响应和对应数据库指纹，而不只信任本地环境变量。
- 清除旧用户的 `QWEN_COMPANION_VOICES_JSON` 登记；私有云文件需要独立 Blob 清理凭据。
- 明确传入 `--apply --confirm=<目标指纹> --approval-file=<授权文件>`。当前没有创建已批准的正式授权文件。

执行时，业务文档和钱包、操作、流水在数据库事务中清空，保留环境绑定。云文件无法与 SQL 共用事务，因此保存清理队列；清理失败时保持维护模式，可重复执行继续清理。确认完成后恢复首次初始化。

应用的 API Key、域名、部署配置不作为业务记录删除。独立克隆工具、桌面原始录音和服务商侧可复用音色不会被这个数据库脚本擅自销毁；如果要销毁这些外部资源，需要在正式清空验收清单中另列范围。静态“示意”素材也不是用户家庭资料。
