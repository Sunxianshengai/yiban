# 主动联系 · 实现与运维

用户已确认默认每天最多一次、可选设备通知、免打扰，测试通过后合并并正式部署。原方案见 `proactive-contact-proposal.md`，本文件记录实际实现边界。

## 行为与数据

新开关按账号＋伙伴分别保存，默认关闭，不把旧的“回来时开场”授权升级成离线通知。自然模式一天最多一次；多聊模式最多三次，全账号滚动二十四小时最多三次，间隔至少四小时。默认上海时区 22:00—08:00 免打扰，可更改。连续两次主动消息未获得用户实际回应时暂停，阅读不会重置计数。“晚点聊”暂停到次日可联系时间。

消息依据只来自本人对相同伙伴的原话回访线索，或该伙伴的有效个人长期记忆。不访问家庭记忆集合，不把主动消息当作用户事实提取。至少有两条用户消息并有近期对话，离最后一条用户消息至少一小时，才有机会联系。模型可判断不合适而不发送；不会为凑次数发送问候。

使用 `proactive_settings`、`proactive_state`、`proactive_jobs`、`proactive_runner`、`notification_subscriptions`、`notification_outbox` 文档集合。来源任务 ID 幂等，数据库比较交换与一次性事务同时提交消息、会话头、频率状态、任务和通知 Outbox。输入、活跃状态、设置、原会话或来源变化时，旧生成结果不提交。原有聊天依然按正常积分规则处理；主动消息不写积分消费操作。

“为什么提起”实时读取原资料，不在任务中重复存一份隐私原文；删除来源后显示不可用。消息在实际发送时间入库，用户重开只读取已存内容。通知链接经过当前登录账号的会话归属校验，可定位消息。主动消息可回应、复制、收藏和朗读；暂不支持将主动消息作为用户请求重新生成。

## 调度与通知

复用公开 GitHub 仓库的 Actions，每小时的 7/22/37/52 分钟调用正式站受保护的 `POST /api/proactive/run`，支持手动运行。工作流不下载代码、不持有模型或数据库密钥，只有 `PROACTIVE_CRON_SECRET`。每次最多处理三个需要模型判断的候选，其他账号轮转；模型失败有退避与重试上限。服务端记录调度心跳。

GitHub 的计划任务可能延迟，公开仓库六十天无活动也可能被自动停用。设置页会提示长期未运行的调度。它实现自然的择时联系，不提供准时闹钟保证；后续需要更高送达 SLA 时可将同一受保护端点改由专用持久调度调用。

Vercel 正式环境变量：`PROACTIVE_CRON_SECRET`、`WEB_PUSH_PUBLIC_KEY`、`WEB_PUSH_PRIVATE_KEY`，可选 `WEB_PUSH_SUBJECT`。私钥和调度密钥仅存加密配置及本地忽略文件，不能提交或写日志。

采用标准 Web Push/VAPID、`manifest.webmanifest` 和仅处理通知的 `sw.js`。Service Worker 不缓存认证页面或 API。权限只在用户点击时请求；不支持或拒绝权限时保留应用内未读。iOS 要求支持的系统版本与主屏幕 Web App。正文默认隐藏，按当前设备选择显示。

订阅仅允许已知浏览器推送服务 HTTPS 地址及有效加密键，避免任意地址请求。订阅绑定账号、端点与登录会话；退出登录会清理该会话的订阅。推送包只有不含正文的任务 ID，Service Worker 使用当前认证会话重新读取通知内容，因此切换账号不会展示上一账号的正文。前台已在应用中时不弹系统通知。推送失败只重试 Outbox，不重复生成聊天或扣分，410/404 清理过期订阅。

## 回退与检查

停用 GitHub 工作流即可停止定时唤醒，也可关闭某个伙伴的主动联系。回退代码不删除个人记忆、家庭资料或已有聊天。通知和会话记录分别保存，设备权限关闭不会撤回聊天。

上线检查包括：正式部署 SHA 与域名、受保护调度的授权、手动调度成功与心跳、Web Push 配置状态、未登录接口被拒绝、标准资源可达，以及登录后设置保存与消息读取。真实设备系统通知仍取决于用户授权和设备支持，不能把模拟推送服务或本地离线测试当作所有设备已送达的证明。
