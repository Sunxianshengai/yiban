# 人生传记影片 · 方案规划

> 目标：把"一堆记忆"变成一部能看、能听、能带走的短片。往回看是一生的传记，往前看是给未来的期盼。
> 状态：待用户拍板，未动工。

---

## 一、一句话方案

**用浏览器把记忆渲染成一部"会动的画册"（零成本、可离线），家人克隆的声音在旁边念旁白；只在 1–3 个高光镜头上花钱调 AI 视频，让老照片真的动一下。**

不是"AI 生成一段视频"（贵、假、不可控），是"你们家的故事 + 你们家的声音"，AI 只负责把片子剪顺、把个别瞬间点活。

---

## 二、为什么这么定（三个判断）

### 判断 1：全 AI 生成视频 = 成本不可承受，且不像你家

按当前百炼定价（[wan2.6-i2v-flash](https://help.aliyun.com/zh/model-studio/wan2-6-i2v-flash)，华北2·北京）：

| 规格 | 单价 |
|---|---|
| 720P（带声音） | 0.3 元/秒 |
| 720P（无声） | 0.15 元/秒 |
| 1080P（带声音） | 0.5 元/秒 |

一部 60 秒的片子纯 AI 生成 = 18 元/次。家庭用户一年做 4 次 = 72 元，而我们没有订阅收入。更关键的是：AI 会**编**——生成出来的画面跟你家老院子没关系，跟"他的回忆"没关系。付费买到的是一次好看的幻觉，不是传记。

### 判断 2：真正的差异化是"有出处 + 有声音"，这两样我们已经有

竞品（Lovia/幽光/幻聊）能生成视频的不在少数，但它们没有：

- **一个有出处的记忆库**（`status:'confirmed'` 的 128 段真实记忆，每句旁白都能点回原文核对）
- **一个已接好的声音复刻管道**（`lib/voice.mjs` + CosyVoice-v3-Flash，1 元/万字符，成员各自音色已存 `members.voiceId`）

所以片子里的旁白是**妈妈自己的声音**在念她自己的回忆——这是竞品拿钱也买不到的东西。技术难度几乎为零，情感密度最高。这一条就是卖点。

### 判断 3：Vercel 上跑不了 ffmpeg，但浏览器里跑得动

Vercel 函数有执行时长与体积限制，塞 ffmpeg 是死路。而浏览器端 `canvas.captureStream()` + `MediaRecorder` 可以零依赖把画面和音轨实时录成视频文件——**渲染成本 0 元，不占服务器，Electron 桌面版还能完全离线出片**。

代价是"实时录制"：60 秒的片子要等 60 秒。可接受（有进度条），后续要快再换 WebCodecs。

## 三、产品形态：一个入口，两个方向

侧栏新增一项 **「人生电影」**，进去后分两个 tab：

### 往回看 · 传记片
从记忆库挑素材 → 编成有章节的短片。
- 素材来源：任意 confirmed 记忆（一个人 / 一段时期 / 某个主题 / 全家）
- 结构：**序章 → 3–5 个章节 → 尾声**，每章 1–3 个镜头
- 每个镜头长这样：`照片（或文字卡）+ 一句字幕 + 一段旁白`
- 旁白音色：可选「默认合成音」或「某位家人复刻的声音」

### 往前看 · 给未来的一封信
不问记忆，问 5 个问题：
1. 你希望三年后的自己在做什么？
2. 有什么话想对十年后的自己说？
3. 你最想留住现在生活里的哪一样东西？
4. 如果有一件事你一定会去做，那是什么？
5. 想对（家人名字）说什么？

答完 → 编成"写给未来的信"→ 同样的渲染管道出片。

> 这个方向价值被低估：它**不需要照片**，年轻人也能用，而且"将来打开看看"自带回访动机（可以埋一个"一年后提醒你回来看"）。建议和往回看同期做，成本只有一套题库 + 一段文案。

## 四、四层能力（从免费到付费）

| 层 | 内容 | 成本 | 依赖 | 建议 |
|---|---|---|---|---|
| **L0 文字传记** | 把记忆编成一篇《人生小传》（章节式文字） | 0 | 已有 `storyFromMemories` 升级 | 必做 |
| **L1 会动的画册** ⭐ | 照片 Ken Burns 缓动 + 淡入淡出转场 + 字幕 + 家人声音旁白 + BGM | **0 元**（浏览器渲染） | 纯前端 | **主体，必做** |
| **L2 活起来的瞬间** | 挑 1–3 个关键镜头，用图生视频让照片动 5 秒，插进 L1 里当高光 | 720P 有声 **1.5 元/个**（0.3×5s） | `wan2.6-i2v-flash` | 可选开关，默认关 |
| **L3 照片开口说话** | 老照片"说"一句祝福（数字人） | EMO 肖像 3:4 **0.16 元/秒**（10 秒≈1.6 元）；wan2.2-s2v 480P 0.5 元/秒 | [wan2.2-s2v / 悦动人像 EMO](https://www.alibabacloud.com/help/tc/model-studio/wan-s2v-overview/) | 二期，且**只对在世家人开放** |

**一部标准传记片的成本**：L1 = 0 元；加 2 个 L2 高光 = 3 元。这比 18 元的纯 AI 方案便宜 83%，而且更像"他们家"。

## 五、技术落点（文件级）

### 新增
| 文件 | 职责 |
|---|---|
| `lib/biopic.mjs` | **核心**。`buildScript({memories, subject, kind, answers})` → 分镜脚本；`localScript()` 本地规则版（无 AI 也能出片）；`promptForScript()` 给模型润色；`estimateDuration()` |
| `components/BiopicStudio.jsx` | 选素材 → 预览分镜 → 播放 → 导出 |
| `components/BiopicPlayer.jsx` | canvas 渲染器 + MediaRecorder 录制器（可复用给分享页） |
| `lib/render.mjs` | 纯函数绘制原语：`drawTextCard / drawPhoto / kenBurns / fade`。不碰 DOM，单测友好 |
| `app/api/biopic/route.js`（或并入 catch-all） | `GET /biopic` 列表+素材池、`POST /biopic/script` 生成、`POST /biopic/save` 存片、`GET /biopic/:id` 读 |
| `tests/biopic.test.mjs` | 脚本生成、时长估算、事实不外溢 |
| `tests/browser/biopic.spec.mjs` | 选素材 → 出片 → 能播放 |

### 修改
- `lib/ai.mjs`：加 `writeBiopic(prompt)`（照抄 `enrichScenes` 的"失败返回 null"模式）
- `app/page.jsx`：NAV 加「人生电影」；`page==='biopic'`；弹窗
- `app/globals.css`：`.biopic-*` 样式层（全 rem）
- `lib/store.mjs`：新集合 `biopics`（走现成的 `put/all/get`，无需改 schema）
- 导出走现成的 `saveMedia()` → 本地写盘 / 线上 Blob 双轨，**不用动**

### 脚本数据结构（关键接口）
```js
{
  id, title: '林阿姨的这些年', kind: 'retro', subjectId: 'member:member-3',
  chapters: [
    {
      title: '一、苏州的老院子',
      shots: [
        {
          kind: 'photo' | 'text' | 'quote',   // 有封面用 photo，没有就降级 text
          memoryId: 'demo-home',               // photo/text 都挂记忆，可点回原文
          caption: '1988 年 · 苏州老家',        // 画面上的一行字
          narration: '老家的院子里有一棵桂花树……', // 旁白（可空）
          durationMs: 6500,
          transition: 'fade' | 'slide' | 'none',
          voiceId: 'cosyvoice-xxx'             // 由渲染层按成员取，脚本里可留空
        }
      ]
    }
  ],
  totalMs: 62000,
  mode: 'local' | 'model'
}
```

### 渲染管道（L1 的核心，约 200 行）
```
1. 脚本 → 逐镜头绘制到 <canvas 1280x720>
   - photo: 封面图 left→right 缓慢 Ken Burns（scale 1.0→1.08 / 1.08→1.0 交替，避免节奏单调）
   - text : 奶油底 + 衬线大字 + 一行年份（复用温柔风格层的色板）
   - 字幕：底部一条半透明米色带，0.8571rem 起
2. 音轨：AudioContext 混音
   - 旁白：每段先调 /api/voice/speak 拿 mp3（已有，带缓存）→ decodeAudioData → 按时间轴排
   - BGM：可选，默认无（避免版权问题）；或内置 2 首 CC0 钢琴曲
   - 混音输出 → MediaStreamDestination
3. canvas.captureStream(30) + 混音音轨 → MediaRecorder
   - Chrome/Edge → webm (VP9/Opus)
   - Safari → mp4 (H.264/AAC)
4. 录完 → Blob → POST /api/biopic/save → saveMedia 落库
```

**降级链（必须做全，否则一定会在某台设备上炸）**：
```
导出 mp4/webm 成功 → 存片
  ↓ 失败
导出「分镜 HTML」（可打印、可在任何浏览器播放）
  ↓ 失败
页面内逐镜头手动播放（"下一段"按钮）
```
分镜 HTML 这条兜底很重要——它本身就是一个可交付物（能发微信、能打印），而且几乎不会失败。

## 六、分阶段路线

| 阶段 | 内容 | 预估 | 交付价值 |
|---|---|---|---|
| **P0** | `lib/biopic.mjs` + 分镜生成 + 页面内逐镜头播放（不导出） | 2–3 天 | 能"看"到片子，可演示 |
| **P1** | canvas 渲染 + 旁白音色接入 + MediaRecorder 导出 + 存片列表 | 3–4 天 | **主功能可用**，能出 mp4 |
| **P1.5** | 「往前看」题库版 | 1 天 | 覆盖没有照片的用户，成本极低 |
| **P2** | L2 高光镜头（1–3 个 AI 动图），带成本确认弹窗 | 2 天 | 卖点升级，按次付费钩子 |
| **P3** | 分享页（只读链接）+ L3 数字人 | 3–5 天 | 传播 / 高端档 |

**建议先做 P0 + P1 + P1.5**（约一周），足够拿去比赛演示：8 段种子记忆 + 已有克隆音色 + 已有 demo SVG 插画，**不需要任何真实素材就能出样片**。

## 七、风险与红线

| 风险 | 应对 |
|---|---|
| 用户没有照片，只有文字 | 文字卡模板必须做得好看（这是默认路径，不是降级路径）。已有 demo SVG 可作占位 |
| 导出在某些浏览器/机型失败 | 三级降级链，最后一定落到"分镜 HTML" |
| 录制要等 60 秒，用户以为卡死 | 进度环 + "正在把记忆一帧帧放进去" + 可后台继续（页面别关） |
| AI 视频成本失控 | L2 默认关闭，出片前必须弹"这一次大约花 X 元，确认吗" |
| **AI 编造家庭事实** | 脚本生成的 system prompt 沿用现有口径：只用记忆里的年份/地点/人物，不确定就写"记得不太清了"，不补细节 |
| **已故亲人的形象/声音** | 传记片默认只用**在世成员**的复刻音色念旁白；L3「照片开口说话」只对在世家人开放，并在 UI 明示 |
| **AI 生成内容标识** | 按《人工智能生成合成内容标识办法》（2025-09-01 施行）：片尾固定一帧"本片由忆伴 AI 辅助生成，故事事实来自家庭记忆库"，L2/L3 镜头角标"AI 生成" |
| 素材授权 | 沿用 `MemoryForm` 的授权勾选；导出页再确认一次"素材已获家人同意" |
| 已删除的记忆还在片子里 | 存片时把脚本快照存一起，删记忆不追溯已出片；但重新生成时必须过滤掉已删/未确认的 |

## 八、需要拍板的事

1. **入口放法**：「人生电影」独立一项（NAV 变 9 项，可能挤），还是和「人生模拟」合并成一个「人生」页的两个 tab？（我倾向合并，侧栏已经很满）
2. **要不要 L2（AI 动图高光）？** 如果第一期就要，等于要接视频生成厂商 + 做付费/配额，工期 +2 天、每片 +3 元。建议**先不做，留接口**。
3. **旁白声音**：默认用浏览器 TTS（免费、机械），还是直接上阿里云复刻音色（更好听、要 `DASHSCOPE_API_KEY`、1 元/万字符）？我建议**优先复刻、TTS 兜底**——这是卖点所在。
4. **导出格式**：接受 webm（Chrome/Edge，无需依赖），还是要硬上 mp4（需引入 muxer 依赖）？建议**先 webm + 分镜 HTML**。
5. **「往前看」做不做在第一期？** 我强烈建议做——成本一天，但能覆盖"没有回忆的年轻人"，也让产品有了"未来"这一维。

## 九、我不建议的做法

- ❌ **上来就接 Sora/可灵做整片**：贵 6 倍、每次效果不可复现、还编造事实。作为"高光镜头"才成立。
- ❌ **在 Vercel 函数里装 ffmpeg**：限制多、冷启动慢、体积爆。浏览器渲染更省钱也更皮实。
- ❌ **让 AI 写整篇传记再直接出片**：一旦它写了一句"那年父亲在码头扛包"而记忆里根本没有，这片子就毁了。必须是"分镜脚本 → 家属可编辑每一句 → 再渲染"。
- ❌ **做成"一键生成"**：传记片的情感价值恰在"家人一起挑素材、一起改字幕"的过程。一键生成反而是把最有价值的部分外包给 AI。
