# AI 人格与表达设置第一版

范围：路线图第一项“AI 人格设置完整生效”。用户确认采用理想陪伴方向，基础字段直接可见，高级表达设置默认折叠。保持现有手机与网页视觉。2026-10-27 用户确认预览并授权合并推送 main、部署正式站及线上检查。

## 已实现行为

- 联系人底部与该人物的更多菜单均可进入“人格与表达”。编辑称呼、角色、年龄、期待、特质、相处背景及关系感受；高级区编辑说话习惯、回复示例、避免的表达。
- 保存通过现有个人 profiles 接口，不消耗积分。每次打开先获取最新个人资料；提交带 expectedUpdatedAt，检测到其他页面已修改时拒绝覆盖，保留输入供核对。
- 保存后后续生成请求读取最新设定，已有消息不改写；已有会话的日常／回忆／整理模式和语气继续生效。
- 关系背景和感受映射为亲近程度、追问节奏与表达边界。理想陪伴不重复伤人的相处方式；严格表达保留尊重与选择权；涉及逝者时保持 AI 身份，不声称代其传话。
- 每项特质具有具体表达指引。高级示例只用于风格，不作为历史消息或家庭事实。用户资料不能改变应用身份、事实来源、权限及计费规则。提示约束仍需模型质量评测，不能保证模型绝不出错。
- voiceName 仍用于设备朗读，avatar 用于展示，不作为文本人格的家庭事实。旧资料缺少高级字段时按空值兼容；创建请求的空高级字段不改变旧版幂等指纹。
- 表单失败保留输入；离开未保存表单会确认；保存期间阻止重复提交。桌面人物摘要与手机单列编辑共用当前设计变量。

## 外部学习与实现边界

先研究 SillyTavern 的角色字段、提示顺序、示例与真实历史的分工，详见 [开源学习记录](research/2026-10-26-persona-open-source.md)。仅借鉴设计与组织方式，未复制其代码、示例角色或资源。用户之后选择 A 方案，因此本版增加折叠的高级表达编辑，超出研究时建议的最小字段范围。

本次不接 Kindroid 服务，不新增长期记忆、实时语音、主动联系、支付或多家庭机制。现有对话、记忆引用、权限和积分链路继续使用原实现。

## 验证与本地预览

`npm test`；`npm run build`；`PW_BASE_URL=http://127.0.0.1:3757 npm run test:e2e:core`。

接口测试校验个人权限、输入边界、清空字段、旧编辑冲突，以及更新后的资料实际进入下一次模型请求，旧消息与积分结算正确。模型响应为模拟；这些测试证明请求和保存行为，不代替自然对话质量测试。

浏览器新增 desktop 1440×1080、mobile 390×844 的编辑流程：默认折叠、展开、保存与刷新、失败保留、免费保存和大字号。预览截图在本机 `.impeccable/review/persona-editor/`，包含 basic、advanced 及 mobile-large-text。示例账号、表单与模型均来自隔离本地测试，不读取真实家庭资料。

上线条件：用户已确认手机及网页预览，正式部署完成状态以对应 main 提交与 Vercel READY 记录为准。

本地结果：100 项单元／接口测试、30 项浏览器功能测试和生产构建通过。独立界面复核为 ship，范围仅为人格编辑预览；设计记录复核确认属于现有设计的延伸，无需修改全站设计系统。桌面“忆伴人格设置预览-待确认”文件夹含 6 张实际页面截图；其中高级区和大字号图为真实滚动位置。用户已批准该视觉方案。
