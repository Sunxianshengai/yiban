# 忆伴 · 主动联系方案与界面预览

日期：2026-10-27。状态：用户已确认本方案；默认每天最多一次，正在完成正式实现与测试。

## 本轮依据与目标

当前基线为 `d5220ef`，已包含暖色聊天界面、自然分条、表情、个人长期记忆，以及 `chat_callbacks` 的话题回访能力。现有回访在用户回来或空会话时提供开场建议，尚没有离线后台调度、真正送达的未读消息和设备推送。本轮要补的是这些链路，而不是再增加一张“开场推荐”卡片。

视觉沿用最新暖色版：米色／桃粉底、白色圆角界面、砖红动作和鼠尾草绿用户气泡；桌面联系人列表＋聊天＋次级设置面板，手机单会话＋全屏设置。家庭记忆保持现状，不参与主动联系取材。

用户已选择「应用内消息＋可选浏览器通知」。用户已确认默认每天最多一次，保留可切换到每天最多三次的选项；次数是上限，不是必须完成的任务。

## 参考 Kindroid，采用什么

[Kindroid 官方 Away proactive actions 说明](https://kindroid.ai/v2/docs/chat-features-and-tools/#away-proactive-actions-guide)描述了结合上下文决定联系、按伙伴设置频率与指令、未回复时逐步退让。官方同时将旧版按离线时长触发的计时器作为 Legacy。拟采用上下文择时、每位伙伴独立偏好、未回应退让和自然进入聊天的方式。

不直接复制它的所有多媒体能力：这一版只做文字与已有受控表情。实时来电、自拍生成、短信、日历接入另立项目。也不展示模拟“内心活动”；「为什么提起」只展示实际可核验的用户原话或记忆依据。Kindroid 是行为参考，不是待调用的底层 API。

## 核心体验

| 场景 | 应该发生的事 | 示例 |
| --- | --- | --- |
| 接着具体安排 | 到合适时间问一句；先确认安排是否仍有效 | 昨天说“明天下午面试” → 今天傍晚“下午的面试，结束了吗？” |
| 熟悉的日常偏好 | 在有近期聊天背景时自然接上兴趣，不把同一偏好每天复述 | 最近多次聊忙碌与花茶 → 偶尔问“下班了吗？要不要留一杯茶的时间。” |
| 聊了一半的小事 | 有明确话题线索才继续；不能把当天情绪固化为永久特征 | 前天说试做陶杯 → 合适时问后来做得怎么样 |
| 用户说晚点聊 | 暂停到下一天可联系时段；立即显示暂停状态 | “晚点聊” → “已暂停到明天 08:00” |
| 没有回复 | 不连环追问，不跨设备重复提醒 | 连续两次主动联系未得到用户回应，暂停到用户再次主动聊天 |
| 事情已结束 | 关闭相应回访线索，其他话题不受影响 | “已经结束，不再提这件事” |

每次主动联系作为一个 AI 消息组写入真实会话，可包含一至两个短气泡及偶尔一个已有表情；同一轮只算一条联系。气泡旁轻量标注“主动联系”，其余交互沿用现有聊天。列表显示真实未读数量，点击通知定位实际消息，不重新生成。

不会假装看到你的现实行为、天气、位置或日程。时间都来自消息时间、明确的用户自述与已验证的设备时区；“明天”绑定原消息日期，已过期计划不继续使用。找不到足够依据就不发，不用空泛的催回话填满配额。

## 节奏与权限的推荐规则

- 主动联系升级后按伙伴明确开启；保留现有“回来时开场建议”的选择，不把旧开关自动升级为离线推送授权。建议在用户与伙伴完成至少两轮交流后展示一次轻提示，不打断聊天。
- 自然模式每天最多一次；多聊模式每天最多三次。第一版全账号每天最多三次，避免多个伙伴一起找用户；两个主动消息组至少间隔四小时。
- 有近期聊天后，约一至三小时起才可能首次联系；具体安排到合适时间优先。不是固定间隔广播，也不是精确闹钟。
- 默认免打扰 22:00—08:00，用户可调，明确显示时区。免打扰同时约束入会话与设备通知；结束后重新判断，不补发整晚积压内容。
- 用户正在输入、最近十分钟活跃、正在生成回复、会话被归档、伙伴已停用、积分服务配置异常或用户刚明确说不想被联系时，不发送。
- “晚点聊／今天安静一会儿”暂停到次日可联系时间。未回复的次数按实际用户发送消息重置，打开页面或已读不算回复。连续两次未回复则暂停，解除需用户回来主动聊天或主动恢复。
- 定向任务只进入同一账号、同一伙伴的专用可用会话。多段历史时选最近未归档的日常会话；没有合适会话时创建一个稳定的“与某伙伴的日常”会话，不能写入用户当前的另一位伙伴或改写历史分支。
- 免费管理开关、次数、免打扰和记忆。推荐主动消息不扣用户积分，用户回复后仍按现有规则每轮成功回复扣一次；模型、调度与推送成本由产品侧预算控制。以后商业化可增加会员主动联系额度，但需明确额度，不能离线悄悄扣积分。

## 页面与交互

1. **会话列表**：沿用当前列表，新增真实未读与最新消息；不增加独立“主动联系首页”。
2. **聊天**：同样的头像、气泡、分条、时间与输入框；主动消息只多一个轻标签。“晚点聊”是可撤销暂停；快捷回复仅填入输入框，由用户确认发送。
3. **聊天详情 → 主动联系**：总开关、两档频率、免打扰；通知入口指向当前设备；自由偏好折叠在高级设置。手机全屏，网页右侧面板。
4. **为什么提起**：展示实际引用的原话及时间，提供“这件事结束了，不再问起”和设置入口。删除或不可用的来源显示已不可用，不复制已删除的全文。
5. **设备通知**：用户点击后才请求权限；默认隐藏正文，可选显示。每个设备分别订阅，但一个主动消息只写一份会话记录。
6. **暂停／拒绝通知／免打扰**：可见且可恢复；拒绝权限后不反复弹框，应用内消息照常。

预览全部使用演示人物与对话。网页里的通知卡是视觉示意，不是系统通知；所有“保存／开启”仅保存在当前预览页面内存，不会请求真实设备权限。

## 实现路径与边界

```text
聊天完成 → 更新私人记忆／话题线索 → 候选任务与版本
                                     ↓
                    服务端定时唤醒／持久任务调度
                                     ↓
                时区、静默、频率、未回应、归属、版本校验
                                     ↓
                      有充分理由才调用模型生成
                                     ↓
                      再校验 → 原子提交会话与未读
                                     ↓
                       通知 Outbox → Web Push
```

调度器只决定检查时机，不能凭空创造消息；不要用网页里的 `setTimeout` 假装离线发送，也不能仅在用户重新打开网页时生成一条冒充早已到达的消息。

拟复用 `personal_memory_scopes`、人格、分条解析和受控表情；整合现有 `chat_callbacks` 作为话题线索，而不是另造第三份“记忆”。现有回访设置按账号、查询可能返回多位伙伴线索，正式实现必须增加账号＋伙伴双重归属检查与独立配置，不能直接当成已具备伙伴隔离的离线发送器。

新增或扩展 `proactive_settings`、`proactive_jobs`、未读游标、`notification_subscriptions`、`notification_outbox`。任务关联来源 ID、来源版本、原会话版本、用户近期活动版本；用户继续聊、修改或删除记忆、关闭功能、归档会话、换时区时取消或重算。生成前后都检查，避免旧后台结果插入新对话。

消息幂等键按候选任务 ID＋账号＋伙伴生成；事务/CAS 保障多次调度和重试仅落一组消息。推送以 Outbox 重试，失败不能重复生成／重复扣积分；数据库写入失败不推送。收到 Web Push 不代表用户已读，通知权限关闭不代表主动联系关闭。消息写入成功与通知送达状态分别记录。

推送订阅按账号和设备绑定；登出清除当前设备关联，换账号不复用上一账号的端点。通知默认不含私密正文；点击后重新验证登录及消息归属。静默适用于所有设备；前台正在查看同一会话时不再额外弹系统通知。

### 部署前必须确认的基础设施

项目目前没有调度配置、Service Worker 或 Web Push 订阅链路。建议 Vercel 保留 Web/API，接入一个持久后台调度来源，每五到十五分钟筛选到期候选；不要为每个用户无条件逐分钟调用模型。

[Vercel 官方限制](https://vercel.com/docs/cron-jobs/usage-and-pricing)：Hobby Cron 每天一次且分钟级时机无保证；若当前是 Hobby，仅依赖它不能实现自然的全天主动联系。若已有 Pro，可用其定时触发；否则评估 [QStash Schedules](https://upstash.com/docs/qstash/features/schedules) 等外部调度，并增加签名验证、退避、幂等与预算。尚未核实当前套餐，本轮没有购买、创建或启用任何云资源。

[WebKit 官方说明](https://webkit.org/blog/13878/)：iOS/iPadOS 16.4 起支持添加到主屏幕的 Web App 推送，权限需由用户手势触发。普通网页、受限浏览器或拒绝权限时应显示具体操作与应用内未读回退，不能承诺所有手机关闭网页都必定弹通知。正式实现须增加 manifest、Service Worker、VAPID 与可靠设备订阅；不需要替用户注册第三方短信服务。

## 正式开发验收清单

- 不同账号、伙伴、会话隔离；旧线索不可跨伙伴出现。
- 当用户离线时真实落库；重开看到原消息及发送时间，不能每次重开重新生成。
- 免打扰跨午夜、设备时区变化、次数上限、未回应退让与恢复。
- 多工作节点并发、任务重复、模型失败、推送失败、记忆删除与用户正在回复时的竞争。
- 不把 AI 主动消息反向提取为用户事实，不让当次语气要求进入长期偏好。
- 文字、气泡、表情与消息版本兼容原聊天；家庭记忆和积分账本回归。
- 桌面与手机：未读、点通知定位、已读同步、开关、暂停、权限拒绝、大字号及键盘操作。

当前只交付方案和独立预览；用户确认后，再实现服务端、接通知、测试，并按新的确认范围部署。
