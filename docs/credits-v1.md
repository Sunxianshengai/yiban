# 管理员发放积分 · 第一版

范围：个人余额、管理员发放、按功能冻结与结算、失败退回、个人流水。不接支付，不提供人民币兑换、转账、提现或自动赠送。

## 使用方式

顶栏“积分”或“更多 → 我的积分”查看可用余额、冻结额度、价目与流水。管理员在同一页面给自己或其他账号发放，必须填写整数数量和说明；所有账号均需支付功能积分。

新旧账号首次启用积分时均为 0。没有积分不影响上传、编辑、发布、搜索和回放已有内容。故事与整理在本地处理时免费。

试运行价目由 `lib/credit-prices.mjs` 管理：整理 2 / 次；家伴与角色对话 1 / 成功回复；声音复刻 30 / 次；合成 2 / 每 100 字向上取整；讲述稿与配音组合 10 / 次；视频 480P 每秒 20，720P 每秒 40。以上为体验积分，不是外部模型的成本或人民币兑换价。前台发起普通生成前确认最高消耗，聊天在输入位置持续显示价格。

## 账户与流水

独立表 `credit_wallets` 保存可用和冻结额度；`credit_operations` 保存请求与任务状态及可重放结果；`credit_ledger` 追加记录管理员发放、冻结、完成、退回。创建表发生在实际积分请求时，兼容现有 SQLite / Neon 数据。

Neon 每次变更均在同一事务里锁定个人账户行；SQLite 使用 BEGIN IMMEDIATE。视频资源另有数据库级唯一活动任务约束，防止不同账号或不同请求标识并发覆盖扣费归属。余额不能为负；发放一次上限 1,000,000，账户可用余额上限 2,000,000,000。发放人与收款人分别记录。后续充值可增加新的受控入账来源与订单标识，不能让客户端自行写余额。

## 请求契约与失败恢复

- `GET /api/credits`：当前用户流水与待处理记录，offset 分页，每页 50 条；不接受其他用户 ID。
- `GET /api/credits/balance`：当前用户的可用与冻结余额。
- `POST /api/credits/grant`：仅管理员，body 为 userId、amount、note。
- 消费和发放请求支持 `Idempotency-Key`。客户端应为每个用户意图生成一个标识，并在网络错误重试时复用；同一标识不同内容拒绝，重复的成功请求重放原结果。未传时兼容旧客户端，由服务端生成独立标识。
- 浏览器传 `X-Credit-Limit` 表示已确认的最高积分；服务端自行报价后比较，超过上限返回 409，请刷新页面重新确认。已冻结任务始终按原金额结算，成功请求重放不受后来改价影响。
- 余额不足返回 402，调用外部模型前停止。重复的处理中请求返回 409 / CREDIT_PENDING；明确已失败的原请求返回 409，用户重新发起应使用新标识。
- 新生成先冻结额度；结果成功并保存后结算，普通请求明确失败后退回。结果先写进消费操作，结算中断后可重放恢复。缓存命中不新增消费。
- 视频任务保存消费操作 ID，创建成功保持冻结；查询临时出错不退回；结果成功转存后结算；任务明确失败、缺少视频地址或结果超出保存大小时退回。重复查询不能重复结算或退回。
- 在“我的积分 → 处理中”可继续查询视频；重新打开记忆详情也恢复轮询。没有定时后台巡检，关闭页面期间要等下次查询才更新结算。服务商状态一直未知时保持冻结，不能根据一次断网直接认定失败。
- 普通请求在打开完整积分页面时恢复：已保存结果自动结算，无结果且中断超过 30 分钟的冻结自动退回。视频创建时若进程中断、超过 30 分钟仍未登记任务，同样退回；已登记且状态未知的视频继续冻结，等待查询。管理员发放不依赖这些恢复步骤。

## 验证与部署

测试使用临时数据库及外部模型模拟响应；不消耗真实模型费用。账户公开接口覆盖发放幂等、并发限额、结算与退款；应用 HTTP 接口覆盖身份权限、成功、失败、缓存、视频异步生命周期。

已有浏览器测试需由管理员给测试账号发放积分；不能为测试给生产账号自动赠送，也不能在生产库运行创建/删除内容的测试。部署不会自动给管理员充值；首次启用后管理员从积分页面发放即可。

此版本不接支付、不中途改变单笔价格，不支持手工修改历史流水。更改价目只影响新请求，冻结中的任务按创建时金额结算。
